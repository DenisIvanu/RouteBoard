# 🚌 RouteBoard

> База данных расписания междугородних автобусов и SQL-запрос для электронного табло отправлений.

Учебно-демонстрационный проект: нормализованная OLTP-схема для управления маршрутами, автобусами и рейсами, а также оптимизированный запрос для отображения ближайших 15 отправлений с заданной остановки на электронном табло.

## 🔀 Граф маршрутов

```
Москва ────── Тверь ────── В. Новгород ────── Псков ────── Санкт-Петербург
  │             │               │               │                │
  │  R1 (сквозной, 5 остановок) │               │                │
  ├─────────────┼───────────────┼───────────────┼────────────────┤
  │             │               │               │                │
  │  R2         │               │               │                │
  ├─────────────┼───────────────┤               │                │
  │             │               │               │                │
  │  R4         │               │  R5           │                │
  ├─────────────┤               ├───────────────┼────────────────┤
  │                             │                                │
  │                             │  R3                            │
  │                             ├───────────────┼────────────────┤
```

| Маршрут | Направление | Остановки | Автобусов |
|---------|-------------|-----------|-----------|
| R1 | Москва → СПб | Москва → Тверь → В. Новгород → Псков → СПб | 6 |
| R1-обратно | СПб → Москва | СПб → Псков → В. Новгород → Тверь → Москва | 6 |
| R2 | Москва → В. Новгород | Москва → Тверь → В. Новгород | 3 |
| R3 | СПб → В. Новгород | СПб → Псков → В. Новгород | 2 |
| R4 | Москва → Тверь | Москва → Тверь | 1 |
| R5 | В. Новгород → СПб | В. Новгород → Псков → СПб | 2 |

Каждый автобус совершает 1–2 рейса в день. Итого ~20–40 рейсов (`trip`) в сутки.

```
                                             │ N:1
                                      ┌──────┴───────┐
                                      │    route     │
                                      └──────┬───────┘
                                             │ 1:N
                       ┌─────────────────────┼─────────────────────┐
                       │                     │                     │
                ┌──────┴───────┐      ┌──────┴───────┐            │
                │     bus      │      │    trip      │            │
                └──────────────┘      └──────────────┘            │
                       │ N:1                 │ N:1                │
                       └─────────────────────┘────────────────────┘
```

### Таблицы

| Таблица | Назначение |
|---------|-----------|
| `city` | Справочник городов |
| `stop` | Остановки (привязаны к городам) |
| `route` | Маршрут (направление) |
| `route_stop` | Упорядоченный список остановок маршрута с относительным временем |
| `bus` | Автопарк (20 автобусов) |
| `trip` | Конкретный рейс: автобус + маршрут + дата + время старта |

## 🚀 Быстрый старт

### Требования

- PostgreSQL 15+
- `psql` или любой SQL-клиент (DBeaver, pgAdmin)

### Развёртывание

```bash
# 1. Создайте базу
createdb routeboard

# 2. Примените DDL
psql -d routeboard -f ddl/01_schema.sql

# 3. Создайте индексы
psql -d routeboard -f ddl/02_indexes.sql

# 4. Загрузите тестовые данные
psql -d routeboard -f ddl/03_seed.sql
```

### Проверка

```sql
-- Сколько рейсов сегодня?
SELECT COUNT(*) FROM trip WHERE trip_date = CURRENT_DATE;

-- Запрос табло для остановки "Тверь" (предположим stop_id = 3)
\i queries/departure_board.sql
```

---

**Параметры:**

| Параметр | Тип | Пример |
|----------|-----|--------|
| `:target_stop_id` | `INT` | `3` (Тверь) |

---

### Ожидаемый план выполнения

```
 Limit  (cost=... rows=15)
   └─ Sort  (Sort Key: departure_time)
        └─ Nested Loop
             ├─ Index Scan on idx_route_stop_stop_id
             │    Filter: stop_id = :target_stop_id
             │    → ~3-5 строк (маршруты через эту остановку)
             │
             └─ Index Scan on idx_trip_date_route
                  Filter: route_id = ... AND trip_date >= CURRENT_DATE
                  → ~10-30 строк (будущие рейсы по маршруту)

             ├─ Index Scan on bus (PK)
             ├─ Index Scan on route (PK)
             └─ Index Scan on stop (PK)
```

**Ключевые наблюдения:**

- **Sort** присутствует, потому что `departure_time` — вычисляемое выражение из двух таблиц. B-Tree не может отсортировать по нему заранее.
- **Index Scan** по `idx_route_stop_stop_id` сужает поиск до нескольких маршрутов.
- **Index Scan** по `idx_trip_date_route` отсекает исторические данные.
- Справочники (`bus`, `route`, `stop`) — десятки строк, целиком в Shared Buffers → сканирование за микросекунды.
- **Ожидаемое время:** 1–5 мс.
